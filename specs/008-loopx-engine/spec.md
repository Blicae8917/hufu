## User Scenarios & Testing *(mandatory)*

本模块的用户仍是在一台电脑上操作本公开仓库的维护者。它交付的是「可选引擎只贡献类型化结果、回执、效果读回和有界恢复」的执行机制纵切。它不是第二套任务系统，不是 LoopX 控制面，不是出站运行时，也不自动开工。

这里的「第一批机制」指：把已批准的机制目录落到 Hufu 自己的引擎服务上——一次有界回合能留下可分类的结果、一份不能当授权的回执、一次读回约束，以及在无进展时停住前向动作。它不把上游的 Goal、Todo、Registry、调度器、心跳或配额搬进 Hufu。

默认路径保持 #6 已交付的入站效果观测。只有操作者显式选择本可选引擎后，才按本规格折叠类型化结果与有界恢复。未选择时，行为与 #6 完全一致。

### User Story 1 - 显式选用可选引擎，默认路径不变 (Priority: P1)

操作者在已连接的工作区里声明：本次执行协调使用可选的 LoopX 机制引擎。系统记下这一选择，但任务正本仍是已经声明的 `github`、`gitlab` 或 `local`。不选用时，查看状态、交接和记下裁决的行为与本模块之前完全相同。引擎不能变成第三种任务正本，也不能从回执或历史运行推导授权。

**Why this priority**: 没有显式选用边界，就会把 LoopX 做成默认控制面或第二套正本。这是本模块最先必须守住的入口。

**Independent Test**: 未选用时，既有连接/状态/裁决夹具结果不变；显式选用后当前视图报告引擎身份为可选引擎且 `task_authority` 仍为原正本；试图把引擎写成任务正本、或把 Goal/Todo/Registry 当作工作项来源的提交被拒绝。

**Acceptance Scenarios**:

1. **Given** 工作区已连接且未选用本可选引擎，**When** 操作者查看状态、做交接或记下裁决/效果观测，**Then** 结果与 #6/#8 已交付合同一致，当前视图不出现引擎正本，也不要求 LoopX 控制面。
2. **Given** 工作区已连接，**When** 操作者显式选用本可选引擎，**Then** 当前视图报告存在可选引擎，且恰好仍只有一个任务正本（原 `github` / `gitlab` / `local`）。
3. **Given** 操作者试图把引擎、LoopX Goal、Todo 或 Registry 声明为 `task_authority` 或工作项生命周期来源，**When** 提交，**Then** 拒绝写入，原连接与授权不变。
4. **Given** 已显式选用本可选引擎，**When** 操作者再次提交相同选用，**Then** 结果与首次成功等价，不产生第二套引擎身份。

---

### User Story 2 - 一次有界回合留下类型化结果 (Priority: P1)

操作者（或当值执行角色）把一次已经发生的有界回合观测交给引擎：回合身份、所属裁决/信封引用、以及该次回合声称的结果类别。引擎折叠出一份类型化结果：这是进展、失败、需读回、需停止还是数据不足。这份结果是执行观测，不是议题状态，也不生成下一步去启动 Agent。

**Why this priority**: 没有类型化结果，回执和有界恢复没有可引用的回合结论。这是机制目录里最先产生可验证引擎输出的一条。

**Independent Test**: 合法入站回合观测得到稳定结果身份与类别；缺少裁决/信封引用或类别无法判定则拒绝；当前视图能读到结果引用与三轴，且工作项生命周期不变。

**Acceptance Scenarios**:

1. **Given** 已选用本可选引擎，且存在当前有效信封，**When** 当值执行角色提交一份字段齐全的入站回合观测，**Then** 系统追加类型化结果，返回稳定结果身份与类别，并引用同一裁决/信封，不改裁决正文。
2. **Given** 回合观测缺少所属裁决或信封引用、类别无法判定、或引用了未选用引擎时不存在的上游 Goal/Todo 身份，**When** 提交，**Then** 拒绝，不得猜测补全。
3. **Given** 类型化结果已保存，**When** 操作者查看状态或做交接，**Then** 输出含结果身份、类别与摘要引用，MUST NOT 把该结果写成工作项已完成或外部议题已关闭。
4. **Given** 同一结果身份再次提交且内容摘要相同，**When** 提交，**Then** 幂等返回原结果；摘要不同则冲突拒绝。

### User Story 3 - 回执只证明核验，读回前不得重试 (Priority: P1)

操作者附上一份类型化回执：针对某次类型化结果或效果身份，声明核验是否通过、依据哪份证据引用。回执不是授权，也不隐含业务完成。若要对同一效果建议恢复或再次观测，必须先有一次读回；读回缺失或覆盖不足时，只能标不可用或数据不足，不能把「没看到」写成零效果或已发生。

**Why this priority**: 这是 Issue #9 的必须交付，也是防止回执/Journal 反向授权、以及无读回重试的硬边界。

**Independent Test**: 合法回执不改变授权修订与工作项生命周期；把回执当授权或完成声明的路径不存在；无完整读回的恢复建议被拒绝；缺失用量或时间不为 `0`。

**Acceptance Scenarios**:

1. **Given** 存在类型化结果，**When** 当值执行角色提交一份只含核验结论与证据引用的回执，**Then** 回执被追加，当前视图能读到回执身份与是否通过，授权修订不变。
2. **Given** 回执试图授予权限、关闭工作项、改写裁决正文或把外部议题标为完成，**When** 提交，**Then** 按合同无效拒绝。
3. **Given** 操作者请求对同一效果做恢复或再次前向动作，**When** 尚无完整读回，**Then** 拒绝该恢复建议，效果槽为不可用或数据不足，MUST NOT 写成 `0`、已发生或确认不存在。
4. **Given** 读回覆盖充分，**When** 记录读回，**Then** 可按 #6 既有效果增量合同标记已发生、确认不存在或数据不足；本模块不得另建第二套效果正本。

---

### User Story 4 - 无进展就停住，绝不调度、心跳或代管议题 (Priority: P1)

当连续有界回合的类型化结果表明没有推进权威目标或验收，或读回确认尚无首个耐久效果时，引擎必须停止建议新的前向动作。恢复是有界的：只允许在既有命令边界上记录读回、遏制和安全恢复建议，不启动调度器、心跳、配额服务，也不自动启动 Agent。任何把上游 Goal/Todo/Registry 映射成 Hufu 工作项或议题生命周期的路径都必须失败关闭。

**Why this priority**: Issue #9 的明确不做全部落在这一条。若恢复变成后台调度，或 Goal 变成正本，本模块即失败。

**Independent Test**: 无进展夹具在 `status`/`handoff` 停止前向动作；调度/心跳/配额/自动开工输入被拒绝；Goal/Todo/Registry 映射测试失败关闭；外部议题身份不变。

**Acceptance Scenarios**:

1. **Given** 已选用本可选引擎且读回充分、首个耐久效果仍确认不存在，同时连续类型化结果无进展，**When** 操作者查看状态或做交接，**Then** 当前视图停止沿旧信封生成新的前向动作，仍允许读回与安全恢复建议。
2. **Given** 输入要求调度器、心跳、配额、周期唤醒或自动启动 Agent，**When** 提交，**Then** 拒绝，不创建后台服务，不发起出站会话。
3. **Given** 夹具把上游 Goal、Todo 或 Registry 条目写成 Hufu 工作项、任务正本或外部议题状态，**When** 折叠当前视图或写入账本，**Then** 失败关闭，不得生成对应工作项。
4. **Given** 任务正本为 GitHub 或 GitLab，**When** 记录类型化结果、回执或有界恢复，**Then** 外部议题生命周期不变，不出现创建、修改、关闭、评论或合并。

---

### Edge Cases

- 未显式选用本可选引擎时，不得因本模块存在而改变 #6 的入站效果观测合同。
- 选用本可选引擎不增加第五种任务正本，也不要求操作者安装上游 LoopX 发行包。
- 类型化结果、回执与读回都是 Hufu 自有执行事实；它们引用既有裁决/信封/效果身份，不复制议题正文或裁决正文。
- 上游回合结果里若夹带调度提示、配额动作、心跳回执或 Goal 刷新指令，必须丢弃或拒绝，不得执行。
- 有界恢复不是 exactly-once，也不是自动重试外部效果；本模块仍不执行外部副作用。
- 写者冲突、损坏账本、未知必需合同沿用既有失败关闭。
- 缺失的墙钟、用量、读回或回合观测不得写成 `0`。
- 本模块不绑定某一个真实客户 LoopX 项目或私有控制面 Endpoint。
- 未知子命令、会商、网页、出站 Runtime、把引擎当任务正本：仍明确失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 操作者 MUST 能在已连接 Project 上显式选用可选引擎。未选用时 MUST NOT 改变既有连接、状态、交接与裁决合同。MUST NOT 把该引擎加入 `task_authority` 枚举。
- **FR-002**: 每个已连接 Project MUST 恰好报告一个任务正本。可选引擎 MUST 只能作为执行机制出现。把引擎、上游 Goal、Todo 或 Registry 声明为正本或工作项来源 MUST 失败关闭。
- **FR-003**: 本模块 MUST NOT 将上游完整控制面作为默认产品依赖引入。门禁与默认安装 MUST NOT 要求取得 LoopX 发行包或私有 Endpoint。
- **FR-004**: 显式选用后，当值执行角色 MUST 能提交入站有界回合观测。系统 MUST 折叠类型化结果（至少区分进展、失败、需读回、需停止、数据不足），并给出稳定结果身份。无法判定 MUST 拒绝，禁止猜测。
- **FR-005**: 类型化结果 MUST 引用既有裁决与信封（及可选效果身份）。MUST NOT 改写裁决正文，MUST NOT 复制议题正文，MUST NOT 把结果写成工作项或外部议题生命周期。
- **FR-006**: 当值执行角色 MUST 能针对类型化结果或效果身份追加类型化回执。回执 MUST 只表达核验结论与证据引用。回执 MUST NOT 产生或扩大授权，MUST NOT 隐含业务完成。
- **FR-007**: Journal、回执、类型化结果、当前视图或恢复建议 MUST NOT 被当作执行授权。`authority_scope_ref` 与授权修订合同保持 #6。
- **FR-008**: 对同一效果建议恢复或再次前向动作之前，MUST 先有完整读回。读回缺失或覆盖不足 MUST 报告不可用或数据不足，MUST NOT 写成 `0`、已发生、确认不存在或已保留。
- **FR-009**: 效果读回与耐久效果标记 MUST 复用 #6 的效果增量合同，MUST NOT 另建第二套效果正本或第二份裁决正文。
- **FR-010**: 当读回充分且首个耐久效果确认不存在，同时连续类型化结果无进展时，CurrentView MUST 停止沿旧信封生成新的前向动作，仍允许读回、遏制与安全恢复建议。MUST NOT 引入调度器、心跳、配额服务、守护进程或周期唤醒。
- **FR-011**: MUST NOT 自动启动 Agent，MUST NOT 创建、继续或投递 Host Session。本模块不做出站 Runtime。
- **FR-012**: MUST NOT 让引擎或上游控制面拥有外部议题生命周期。GitHub / GitLab 正本下，本模块全部路径 MUST 保持只读投影合同。
- **FR-013**: 边界测试 MUST 证明：上游 Goal、Todo、Registry 条目不会被映射为 Hufu 工作项、任务正本或授权。夹带调度、心跳或配额动作的输入 MUST 被拒绝或丢弃且不执行。
- **FR-014**: 若实现复制或改编上游源码，MUST 按该次采用所针对提交的许可证保留归属，并更新公开 NOTICE。本模块默认不复制上游源码；未更新 NOTICE 的源码搬入 MUST 视为不合格。
- **FR-015**: CurrentView 的每项重要事实 MUST 继续携带三轴。引擎相关事实 MUST 为观测值或派生值，不是权威任务生命周期。缺失墙钟、用量或读回 MUST NOT 写成 `0`。
- **FR-016**: `connect` / `doctor` / `status` / `handoff` / `decide` 的退出码族、机器可读 JSON 与 `validate` 合同 MUST 保持。本模块允许在既有命令上增加显式选用与入站引擎观测，MUST NOT 增加网页服务、会商或出站命令。
- **FR-017**: 实现任何新的可观察行为前 MUST 先有一条会失败的测试。门禁 MUST 不依赖实时网络、真实 LoopX 控制面或真实外部效果执行。版本保持 `0.1.0`。
- **FR-018**: MUST NOT 修改 Host Agent Loop。引擎特定状态与策略 MUST 放在 Adapter / Provider 之后，不得进入供应商中立核心的任务正本模型。
- **FR-019**: Windows 与 POSIX MUST 都能完成未选用对照、显式选用、类型化结果、回执与无进展停止的验证，无需后台服务。

### Key Entities

- **EngineBinding**: 可选引擎选用记录；指向已连接 Project，不是 `task_authority`。
- **TypedResult**: 一次有界回合的类型化结论：稳定身份、所属裁决/信封引用、类别、观测时间、摘要。不是工作项状态。
- **Receipt**: 针对结果或效果的类型化核验声明；不产生授权，不隐含完成。
- **EffectReadback**: 对稳定效果身份的读回观测；约束恢复建议；复用 #6 效果增量。
- **BoundedRecovery**: 无进展或读回约束下的停止/遏制/安全恢复建议；不是调度器，不是自动重试。
- **CurrentView**: 与既有模块同一视图合同家族；可展示可选引擎与类型化结果，不得把它们显示成任务正本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 按快速开始，操作者能在 15 分钟内于 Windows 或 POSIX 上完成：连接 →（可选）选用引擎 → 提交一次类型化结果 → 查看状态，并得到机器可读成功结果（两类环境各至少一次）。
- **SC-002**: 未选用引擎的既有夹具 100% 与本模块之前的连接/状态/裁决结果一致。
- **SC-003**: 显式选用后，100% 样例仍恰好报告一个任务正本，且该正本不是引擎。
- **SC-004**: 合法类型化结果样例 100% 带稳定身份、类别与裁决/信封引用；无法判定或引用 Goal/Todo/Registry 当工作项的样例 100% 失败关闭。
- **SC-005**: 回执样例 100% 不改变授权修订与工作项生命周期；把回执当授权或完成声明的输入 100% 被拒绝。
- **SC-006**: 无完整读回却请求恢复的样例 100% 被拒绝，对应槽位不是 `0`、已发生或确认不存在。
- **SC-007**: 无进展夹具在 `status`/`handoff` 100% 停止新的前向动作；调度/心跳/配额/自动开工输入 100% 失败关闭且不出现后台服务。
- **SC-008**: Goal/Todo/Registry 映射夹具 100% 不产生 Hufu 工作项；GitHub/GitLab 正本下本模块路径 100% 无议题写回。
- **SC-009**: 门禁 100% 不依赖上游发行包或实时 LoopX 网络；公开仓不出现未声明许可证的上游源码。

## Assumptions

- 本模块用户是本公开仓维护者。引擎选用由操作者在已连接工作区显式声明；不从 git remote、LoopX 目录或环境变量自动探测控制面。
- 默认不复制、不改编、不 vendoring 上游源码，也不把 LoopX 发行包列为默认产品依赖。机制以 Hufu 自有合同重新表达。若后续 Plan 决定复制或改编，必须钉死提交、按该提交许可证更新 NOTICE，并先核对 ADR 0003 中的许可证表述。
- 2026-08-16 公开复核：已接受机制核对本仍为提交 `58f545aee1ce00c57b7a4f21b13d78ee0367b3da`（相关发布 `0.4.7`，MIT）。公开 `main` HEAD 为 `8c103dfecae0f4424ecb0b07bad7cbc5f0797d6d`（发布 `v0.4.8`），相对核对本超前 47 个提交；该 HEAD 主许可证为 Apache-2.0，并保留 `LICENSE-MIT` 说明 `v0.4.7` 及更早为 MIT。HEAD **不是**本模块已接受实现基线，须由 Plan 在源码复盘后决定是否改钉。
- 类型化结果的类别最小集合为：进展、失败、需读回、需停止、数据不足。上游若还有调度提示或配额动作，本模块只拒绝或忽略，不执行。
- 有界恢复沿用 #6 的既有命令边界（`status` / `handoff` / `decide` 效果增量），不新增守护进程，不新增产品级出站命令。
- 门禁使用公开安全夹具，不写客户项目名、本机路径或私有 Endpoint。
- 版本保持 `0.1.0`。不采集效能试点（属 #10）。不引入新的 Cordis 插件作为本模块交付物；Standalone 命令路径上的引擎服务即可。DeepSeek 入口若消费本服务，必须复用同一合同，且仍不修改 Agent Loop。
- 本模块不阻塞 `0.1.0` 发布。

## Out of Scope

- 把 LoopX 作为 `task_authority`，或映射 Goal / Todo / Registry 为 Hufu 工作项
- 引入 Scheduler、Heartbeat、Quota、Lease、后台唤醒或自动 Agent 启动
- 将上游完整控制面作为默认依赖或默认引擎
