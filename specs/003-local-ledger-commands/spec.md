# Feature Specification: 本机账本与四个有界命令

**Feature Branch**: `003-local-ledger-commands`

**Created**: 2026-08-15

**Status**: Draft

**Input**: User description: "GitHub Module Issue #3（M2）：实现本机 `local` 只追加账本，以及四个有界命令 connect / doctor / status / handoff。CurrentView 必须能区分事实来源、可用性和时效。不实现完整决策状态机，不接入 GitHub / GitLab，不引入插件运行时、网页或出站运行时。"

**Parent Issue**: [#3](https://github.com/Blicae8917/hufu/issues/3)

## User Scenarios & Testing *(mandatory)*

本模块的用户是在一台电脑上操作本仓库的维护者或贡献者。它交付的是「本机可连接、可检查、可查看、可交接」的最小协调纵切，不是跨机器任务系统，也不是完整决策流。

### User Story 1 - 第一次把本机项目连上并立下授权 (Priority: P1)

操作者在一个工作目录里声明：这是一个本机正本项目、谁是指挥官、授权范围是什么、谁先当项目负责人。系统按固定顺序记下连接、指挥官身份、第一份授权和第一个项目负责人绑定，之后同一目录里的检查与查看都认这一套记录。

**Why this priority**: 没有连接与授权本体，后面的健康检查、当前视图和交接都没有正本可依。这是发布门四命令里最先产生持久结果的一步。

**Independent Test**: 在空工作区完成一次本机连接后，能读到恰好一份本机正本、一份指挥官身份、一份授权和一份当值项目负责人；重复提交相同内容不产生第二套身份；冲突时拒绝写入且不假装成功。

**Acceptance Scenarios**:

1. **Given** 工作区尚未连接，**When** 操作者以本机正本完成连接并给出指挥官身份与授权范围，**Then** 系统按「连接 → 指挥官身份与首份授权 → 首个项目负责人绑定」记下冷启动，并返回机器可读成功结果。
2. **Given** 已经用同一组身份与范围成功连接，**When** 操作者再次提交相同连接，**Then** 结果与首次成功等价，账本不出现互相矛盾的第二套冷启动记录。
3. **Given** 已经连接为本机正本，**When** 操作者再次连接却改成不受支持的正本、另一个指挥官或另一份不同授权，**Then** 写入被拒绝，原记录保持不变，退出表示状态冲突。
4. **Given** 另一写者正在写入或无法确认当前只有一个写者，**When** 操作者尝试连接或追加，**Then** 写入被拒绝，不得排队接管或静默覆盖。

---

### User Story 2 - 检查本机是否健康、能否安全继续 (Priority: P1)

操作者在动手看状态或交接之前，先问「这台机器上的配置和账本现在能不能用」。系统只报告、不改外部系统：缺连接、正本不受支持、账本读不到、记录损坏、写者冲突或观测不够用时，给出稳定的失败类别。

**Why this priority**: 本机账本损坏或锁冲突时，直接查看会误导。健康检查是操作者判断「现在能不能写、该不该停」的入口。

**Independent Test**: 对健康账本给出成功报告；对缺失、冲突、损坏或未完成追加给出对应失败类别；默认不修改账本。

**Acceptance Scenarios**:

1. **Given** 已完成合法冷启动且账本完整，**When** 操作者做健康检查，**Then** 得到机器可读成功报告，指出本机正本可访问，且不改写外部系统。
2. **Given** 工作区尚未连接或账本目录不可读，**When** 操作者做健康检查，**Then** 报告配置或本地状态不可用，退出表示观测不可用或数据不足。
3. **Given** 账本最后一条记录因中断而未写完，**When** 操作者做健康检查，**Then** 该条被标为冲突或未完成，系统提出需操作者确认的截除建议，默认不自动修复。
4. **Given** 账本中间出现无法解释的损坏记录，**When** 操作者读取或检查，**Then** 整个账本判定为不可用，读写都拒绝，不得静默跳过坏行。
5. **Given** 操作者显式确认执行截除建议，**When** 仅最后一行未写完，**Then** 系统去掉该未完成行并追加一条修复记录；未确认时不得截除。

### User Story 3 - 从一份当前视图看清事实能不能用 (Priority: P2)

操作者查看当前项目：正本是什么、谁是项目负责人、有哪些本机工作项、授权还在不在、下一步是否越权。每一项重要事实都分开标明：这是权威值、观测值还是推产值；现在能不能安全使用；时效是新、旧、未知还是不适用。默认不访问网络。

**Why this priority**: 发布门要求操作者不再靠第二份清单拼状态。连接与健康检查之后，当前视图是日常入口。它依赖账本已存在，故排在 P2，但仍属本模块必须交付。

**Independent Test**: 连接成功后查看当前视图，能区分三轴事实；缺失观测显示不可用或数据不足，不写成数值零；未改动的账本多次查看结果相同。

**Acceptance Scenarios**:

1. **Given** 已完成本机冷启动，**When** 操作者查看当前状态，**Then** 能识别任务正本、项目负责人、授权引用，以及（若已有工作项）工作项列表；每项重要事实带有来源类别、可用性与时效。
2. **Given** 某个角色、工作项或观测尚不存在，**When** 操作者查看当前状态，**Then** 对应事实的可用性为不可用或数据不足，不得用 `0`、猜测的完成态或空当值冒充「没有问题」。
3. **Given** 账本自上次查看后未被改写，**When** 操作者再次查看或完整回放，**Then** 得到相同的工作项与绑定视图。
4. **Given** 默认查看路径，**When** 操作者请求当前状态，**Then** 不发起网络读取；若请求尚未提供的显式刷新，则按合同/输入无效拒绝，而不是悄悄联网。

### User Story 4 - 留下交接且下一步不越权 (Priority: P2)

操作者结束一段本机工作时，记录已完成、剩余工作、风险和下一次审阅点。生成的下一步文本标明所选工作项，并且不超出已经记下的授权范围。交接本身不扩大授权、不改写任务正本。

**Why this priority**: 四个有界命令缺一不可；交接是本模块唯一写入「执行协调事实」的日常命令，也是后续模块做影子试点的起点。

**Independent Test**: 对已存在的本机工作项留下交接后，当前视图能读到该交接摘要；下一步文本含工作项身份且不超出授权；无工作项或无授权时失败类别明确。

**Acceptance Scenarios**:

1. **Given** 已连接且账本中存在指定本机工作项与有效授权，**When** 操作者提交交接，**Then** 账本追加一条交接记录，成功结果为机器可读，并包含不越权的下一步文本。
2. **Given** 指定工作项不存在或授权范围无法覆盖所请求的下一步，**When** 操作者提交交接，**Then** 拒绝写入；前者视为数据不足，后者视为合同/输入无效或状态冲突（以能否判定范围为准），均不得扩大授权。
3. **Given** 写者冲突或账本不可用，**When** 操作者提交交接，**Then** 写入被拒绝，已有记录不变。

---

### Edge Cases

- 本机账本只对本安装、本工作目录有效；复制目录到另一台电脑不构成共享正本，目标机器必须视为未连接或冲突，不得自动合并。
- 同时有两个写者、锁文件已存在、或无法确认唯一写者时，任何追加都必须失败，不得等待、抢锁或删除他人锁。
- 相同幂等键且内容摘要相同：返回原结果，不追加第二条。相同幂等键但内容摘要不同：拒绝写入。
- 记录顺序以账本序号为准；墙上时钟相同或回拨不得改变顺序，也不得用写者局部序号代替全序。
- 读取遇到未知的、且合同标明必需的未来版本时失败关闭，不得猜测升级。
- 旧版本记录只在读取时升级为当前理解，原始行不得改写。
- `validate` 最小信封校验保持原行为；本模块不得把它改成 `local` / `github` / `gitlab` 正本模型。
- 请求 GitHub 或 GitLab 正本、联网刷新、网页服务或出站运行时：明确失败，不创建那些能力的运行态。
- 健康检查默认只读；只有操作者显式确认的「截除未写完的最后一行」可以改账本，且必须留下修复记录。
- 缺失的用量、墙钟或观测不得写成 `0`。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 操作者 MUST 能把当前工作目录连接为一个 `task_authority=local` 的 Project，并记录仓库身份；MUST NOT 存储 Provider 凭据。
- **FR-002**: 冷启动 MUST 按固定顺序追加：Project 连接、指挥官身份与第一份 `AuthorizationGrant`、第一个当值 `project_lead` 绑定。引导记录允许引用同一次引导中声明的指挥官身份；引导之外的记录 MUST 引用已存在的绑定。
- **FR-003**: `AuthorizationGrant` MUST 作为授权的唯一记录本体存在，至少包含稳定身份、修订号、可归因签发人、范围字段、有效期与 `supersedes`。范围字段在本模块允许以自由文本填充，但字段本身 MUST 存在。修改或收回 MUST 追加新修订，不得改写历史。
- **FR-004**: 每个已连接 Project MUST 恰好报告一个任务正本。本模块只实现 `local`；`github` 与 `gitlab` MUST 以不受支持失败关闭。
- **FR-005**: 已连接且活跃的 Project MUST 恰好有一个当值 `project_lead`。指挥官是人类身份记录，不要求会话绑定。
- **FR-006**: 本机账本 MUST 为单安装、单写者边界：追加前 MUST 排除并发写者；冲突或无法确认唯一写者时 MUST 拒绝写入。`writer_id` 只用于诊断，不得代替账本全序，也不得使并发写入合法化。
- **FR-007**: 每条持久记录 MUST 使用共享事件信封，至少包含稳定事件身份、事件类型、该类型的合同版本、账本范围的权威序号、发生时间、行动者引用、因果引用、幂等键与内容摘要。
- **FR-008**: 内容摘要 MUST 按已接受规范计算：先对合同规定的语义字段做规范化序列化，再取 SHA-256；同一输入在受支持平台上 MUST 得到逐字节相同的摘要。规范化规则的版本 MUST 可识别；更换算法 MUST 提升该版本并保留旧版本校验路径。
- **FR-009**: 账本 MUST 只追加。当前视图 MUST 由确定性回放得到。对未改动的合法账本回放，WorkItem 与绑定视图 MUST 相同。
- **FR-010**: 旧记录 MUST 只在读取时通过无副作用规则升级；原始记录 MUST NOT 被重写。未知必需未来版本、无法建立全序、摘要冲突、因果缺失或中间行损坏 MUST 失败关闭。
- **FR-011**: 文件中间出现畸形记录时，整个账本 MUST 判定为损坏。仅最后一条因中断截断时，MUST 报告为未完成追加（可用性为冲突）；默认不修复。操作者显式确认后，系统 MUST 只截除该未完成尾部并追加修复记录。
- **FR-012**: `connect`、`doctor`、`status`、`handoff` MUST 输出机器可读结果，并使用统一错误合同（独立合同版本）。失败类别至少区分：合同或输入无效、任务正本缺失或不受支持、并发写者冲突、账本因果或摘要冲突、不支持的合同版本、观测不可用或数据不足。退出码族 MUST 为：`0` 成功、`2` 合同或输入无效、`3` 状态冲突或并发拒绝、`4` 观测不可用或数据不足。消费者 MUST NOT 靠解析人类可读句子判断失败类别。未知子命令可继续用非这四者的退出码，但不得创建运行态。
- **FR-013**: `doctor` MUST 报告配置缺失、不受支持的正本、本地状态不可访问、写者冲突、损坏或未完成追加，且默认不修改外部系统、不联网。
- **FR-014**: `status` 默认 MUST 只读本地账本（及可重建的本地派生缓存），展示观测时间与时效；MUST NOT 默认联网。本模块 MUST NOT 提供成功的显式刷新路径（属后续外部投影模块）。
- **FR-015**: CurrentView 的每项重要事实 MUST 独立携带 `fact_class`（`authoritative` / `observed` / `derived`）、`availability`（`available` / `unavailable` / `data_insufficient` / `conflict`）与 `freshness`（`fresh` / `stale` / `unknown` / `not_applicable`）。面向用户的综合标签若出现，也只是派生，不得写回为新正本。
- **FR-016**: `handoff` MUST 记录已完成工作、剩余工作、风险与下一审阅点，不得扩张授权或改写任务正本。成功时的下一步文本 MUST 标识所选 WorkItem，且 MUST NOT 超出已记录 `AuthorizationGrant` 的范围。
- **FR-017**: 本模块 MUST 能记录本机 WorkItem 生命周期事件，供状态与交接引用。四个用户命令之外 MUST NOT 再增加第五个产品命令；测试与领域服务可以追加本机工作项记录。尚无工作项时，状态中与工作项相关的事实 MUST 标为数据不足，而不是伪造一个工作项。
- **FR-018**: 本模块 MUST NOT 实现完整决策状态机（执行信封、路线确认、三类增量、语义重基），MUST NOT 接入 GitHub / GitLab，MUST NOT 引入插件运行时、网页、出站运行时、数据库、消息队列、守护进程或后台刷新。
- **FR-019**: 本模块 MUST NOT 把本机账本当成可跨电脑共享的正本。本地运行态位于工作区 `.hufu/`，MUST 排除在版本控制之外。
- **FR-020**: Windows 与 POSIX MUST 都能完成连接、健康检查、查看与交接的验证，且无需后台服务。
- **FR-021**: 实现任何新的可观察行为前 MUST 先有一条会失败的测试，再写生产代码。
- **FR-022**: 当前开发版本保持维护者已批准的 `0.1.0`；本模块 MUST NOT 自行提升版本的前两位。`validate` 的既有成功/失败合同 MUST 保持。

### Key Entities

- **Project**: 一次本机连接：工作区、仓库身份、恰好一个 `task_authority`。不存凭据。
- **AuthorizationGrant**: 指挥官签发的授权记录本体；是后续范围引用的唯一来源。
- **CommanderIdentity**: 人类指挥官身份；冷启动时声明，不要求会话绑定。
- **RoleBinding**: 角色与项目或工作项的当值关系；本模块冷启动必须产生当值 `project_lead`。不授予目标或授权。
- **WorkItem**: 本机正本拥有的工作单元。本模块可记录其打开与展示，不复制外部 Issue 生命周期。
- **Handoff**: 已完成、剩余、风险与下一审阅点；不扩大范围。
- **EventEnvelope**: 每条账本记录的共享外壳（身份、类型、版本、序号、时间、行动者、因果、幂等键、摘要）。
- **CurrentView**: 从权威记录、自有观测和派生事实折叠出的确定性视图；带视图合同版本；不是第二份任务正本。
- **FactAxes**: 每项重要事实上的来源类别、可用性与时效三轴。
- **CommandError**: 四个命令共享的机器可读错误，含稳定错误码与合同版本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 未接触过本模块的操作者，按快速开始能在 10 分钟内于 Windows 或 POSIX 上完成本机连接，并得到机器可读成功结果（两类环境各至少一次）。
- **SC-002**: 冷启动成功后，账本中可核对到恰好一次连接、一份指挥官身份、一份授权和一份当值项目负责人，顺序固定；100% 的合法相同重提不产生冲突身份。
- **SC-003**: 在写者锁已存在或故意并发写入时，100% 的追加尝试被拒绝，原账本字节（除锁诊断外的事件记录）不变。
- **SC-004**: 对同一份未改动的合法账本连续回放 3 次，当前视图中的工作项集合、绑定与授权引用 100% 相同。
- **SC-005**: 分别调用四个命令的成功与各类失败样例时，100% 返回约定退出码 `0/2/3/4` 之一（成功或该命令的失败类别），且标准输出含可解析的结果或错误码字段。
- **SC-006**: 当前视图抽查的每项重要事实都能读到来源类别、可用性与时效；人为制造的缺失观测 100% 显示不可用或数据不足，不出现用 `0` 填充的用量或完成计数。
- **SC-007**: 交接成功样例的下一步文本含所选工作项身份，且人工对照授权范围时不越权；无工作项或范围不足时 100% 失败并保持账本不变。
- **SC-008**: 验证过程不启动后台服务、不要求网络；对 GitHub/GitLab 连接请求 100% 明确失败。

## Assumptions

- 目标用户是本仓库维护者在单台电脑上的操作；跨机器共享任务状态应等后续 GitHub 正本模块，不在本张票发明同步。
- 本机物理账本采用已接受的 Standalone 格式：工作区 `.hufu/ledger/events.jsonl`，一行一条完整记录，换行统一为 LF。锁文件为 `.hufu/ledger/write.lock`，用「独占创建」取得；取锁失败立即拒绝，不排队、不超时等待、不删除他人锁。锁内写入 `writer_id`、进程号与创建时间仅供诊断。崩溃留下的锁视为写者冲突，由操作者在确认无写者后手工删除锁文件；本模块不提供自动清锁命令。
- `connect` 必填：项目标识、仓库身份、`task_authority=local`、指挥官标识、授权范围文本。项目负责人标识可省略，默认等于指挥官。不从 git remote 自动探测仓库，以免暗含网络或本地 git 耦合。
- 冷启动四条引导记录视为同一次引导事务：要么全部成为合法前缀，要么整次连接失败且不留下半套身份。重提相同引导视为幂等。
- 授权范围在 `0.1.0` 以自由文本填入结构化字段（仓库、路径 glob、命令类别均可先用文本）；本模块做「下一步不得超出已记录文本范围」的字面包含检查，不做 glob 引擎。有效期缺省为未设置（长期有效），若调用方传入则必须是可解析的终止时间。
- 本模块不提供第五个产品命令来创建工作项。领域服务提供「打开本机工作项」供测试与后续命令使用；`handoff` 必填工作项标识。
- `status` 不接受成功的刷新选项；传入刷新类参数视为合同无效（退出码 2）。本地权威事实的时效为 `not_applicable`；本机观测事实默认为 `fresh`。过期阈值记录为项目级默认 24 小时，供后续外部投影使用，本模块不据此把本机正本标为过期。
- 四个新命令的机器可读结果写到标准输出（一个 JSON 对象）。`validate` 保持 M1：成功摘要在标准输出，失败理由在标准错误。未知子命令退出码 `1`，与 M1 一致。
- 错误码稳定字符串至少包括：`CONTRACT_INVALID`、`TASK_AUTHORITY_UNSUPPORTED`、`TASK_AUTHORITY_MISSING`、`LEDGER_WRITER_CONFLICT`、`LEDGER_CAUSALITY_CONFLICT`、`LEDGER_DIGEST_CONFLICT`、`LEDGER_CORRUPT`、`SCHEMA_UNSUPPORTED`、`OBSERVATION_UNAVAILABLE`、`DATA_INSUFFICIENT`、`GRANT_SCOPE_EXCEEDED`。
- Session 与 Run 作为可记录实体进入数据模型，但本模块不提供开始会话或开始运行的产品命令；缺失时在当前视图标为不可用或数据不足。
- 规范化序列化采用 RFC 8785，再 SHA-256；具体实现（自研有界规范化器还是依赖库）由 Plan 决定，规格只要求跨平台摘要一致。
- 版本保持 `0.1.0`。不采集效能试点。不把 `0.0.1` 的 `native`/`external` 信封自动迁成账本数据（该基线无持久运行态）。

## Out of Scope

- 完整决策状态机：`DECISION_PACKET` 全文保存策略以外的执行信封、路线确认、三类增量、语义重基（本模块若完全不碰决策记录，不得假装已实现零拷贝决策流）
- GitHub / GitLab 只读投影与显式刷新联网
- Cordis 运行时、DeepSeek 插件、Web Console、MCP、出站 Runtime、LoopX
- 跨机器同步、数据库、消息队列、守护进程、心跳、配额、多主机协调
- 自动启动 Agent、外部写回、清锁自动化、第五个产品命令
- 把 `validate` 升级为新正本模型
