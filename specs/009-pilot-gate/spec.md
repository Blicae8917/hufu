## User Scenarios & Testing *(mandatory)*

本模块的用户仍是在一台电脑上操作本公开仓库的维护者。它交付的是「把一次代表性工作记成可比较的效能试点，并用三轮结论决定是否允许扩充呈现层」的门禁纵切。它不是网页控制面，不是远程服务，也不是第二套任务系统。

这里的「试点」指：从指挥官接受一项工作或一组相关工作的目标开始，到对应交接与验收结论被接受为止，与同类人工项目经理或单 Agent 基线比较。它必须按产品规范分别留下规划墙钟、执行墙钟、总墙钟、人工协调时间、零效果尝试、协调唤醒、返工、设置成本和可取得的原生用量。结论只能是净收益、无净收益、权衡、数据不足或失败。

默认路径保持已交付的连接、状态、交接、裁决与可选引擎。本模块不得因为 Issue 存在就启动网页。网页若进入实现，必须同时满足：三轮可比较试点给出可解释净收益，以及维护者另一次明确批准。未满足时，网页、远程接口与其它新控制面保持关闭。

### User Story 1 - 为一次已结束的工作记下试点结论 (Priority: P1)

操作者在已连接的工作区里，把一次已经完成交接与验收的工作标为一份效能试点：声明比较对象类别、基线来源、以及唯一结论。系统保存这份试点身份，并要求所有规范列出的度量槽位都有值：实测、不可用或数据不足，不得用「没看到」填成零。

**Why this priority**: 没有可引用的试点记录，三轮门禁无法求值，公开仓也会被原始数据或口头结论填满。这是本模块最先必须守住的入口。

**Independent Test**: 字段齐全的试点得到稳定身份与合法结论；缺少工作引用、结论不在允许集合、或用单一用量/步骤数宣称成功的提交被拒绝；未记录试点时既有状态/交接合同不变。

**Acceptance Scenarios**:

1. **Given** 工作区已连接，且目标工作已有被接受的交接与验收结论，**When** 操作者提交一份字段齐全的试点记录，**Then** 系统追加试点身份，结论为允许集合之一，并引用同一工作，不改任务正本与授权。
2. **Given** 试点缺少工作引用、缺少结论、结论不在净收益/无净收益/权衡/数据不足/失败之中，或用单一用量、自动化步骤数量宣称成功，**When** 提交，**Then** 拒绝，不得猜测补全。
3. **Given** 尚未记录任何试点，**When** 操作者查看状态、做交接或记下裁决，**Then** 结果与本模块之前一致，不要求网页服务，也不出现第三种任务正本。
4. **Given** 同一试点身份再次提交且内容摘要相同，**When** 提交，**Then** 幂等返回原记录；摘要不同则冲突拒绝。

### User Story 2 - 从已有事实派生可比较度量，缺失不得写成零 (Priority: P1)

操作者查看一份试点时，系统按产品规范折叠度量：协调唤醒来自推进同一工作的显式介入计数；零效果尝试来自结束时没有新的耐久效果、新证据或新决策增量的执行尝试；返工来自针对同一验收目标的取代或重做；编排墙钟只统计操作者驱动的协调间隔；模型推理时间归入执行墙钟。无法取得的墙钟或原生用量必须标为不可用，不得摊派估算，也不得写成 `0`。

人工基线是带来源的观测，在私有环境采集后按字段白名单导入；不是 Hufu 自己测到的用量不得标为实测。

**Why this priority**: Issue #10 的必须交付就是这些操作定义。若缺失被写成零，门禁会被伪造的「便宜」通过。

**Independent Test**: 合成账本夹具能得到与事件一致的唤醒/零效果/返工计数；去掉墙钟或用量后对应槽为不可用或数据不足且不是 `0`；把估算用量标成实测的输入被拒绝。

**Acceptance Scenarios**:

1. **Given** 一份合成账本含可识别的命令、交接、效果读回与决策增量，**When** 操作者查看该试点度量，**Then** 协调唤醒、零效果尝试与返工的计数与规范定义一致，且可追溯到已有事件，不复制议题正文或裁决正文。
2. **Given** 墙钟、原生用量或基线观测缺失，**When** 折叠度量，**Then** 对应槽为不可用或数据不足，MUST NOT 为 `0`，MUST NOT 用字符估算冒充实测用量。
3. **Given** 操作者导入人工基线，**When** 基线带来源与观测时间且不含私有路径或客户项目名，**Then** 基线作为观测事实保存；缺少来源或试图写入本机绝对路径、内部项目名、凭据时拒绝。
4. **Given** 试点结论为净收益，**When** 查看依据，**Then** 能同时看到质量/安全/证据完整性未因缩短时间或降低用量而退化的声明槽；仅凭用量变少不得得到净收益。

### User Story 3 - 三轮可比较结论决定是否允许扩充，默认不做网页 (Priority: P1)

维护者查看扩充门禁：是否已有三轮声明为同类的代表性试点，以及它们的结论。只有三轮均可解释为净收益时，门禁才报告「允许评估本机回环网页」。即便门禁打开，本模块也不得自动实现网页；网页必须另有明确批准。任一轮为无净收益、权衡、数据不足或失败，或还凑不齐三轮，则暂停网页、远程接口和其它新控制面，既有核心合同不被否定。

**Why this priority**: Issue 写明网页不能因为本任务存在就默认要做，且连续三轮无净收益必须停。这是防止控制面膨胀的硬边界。

**Independent Test**: 零轮或不足三轮时网页/远程入口保持关闭；三轮无净收益时关闭并允许复盘记录；夹带「因本模块存在而启动网页」的路径不存在。

**Acceptance Scenarios**:

1. **Given** 可比较试点不足三轮，或任一轮结论不是净收益，**When** 操作者请求本机网页、远程绑定或其它新控制面，**Then** 拒绝，不创建后台服务，不监听非本机地址。
2. **Given** 已有三轮声明同类且结论均为可解释净收益，**When** 查看门禁，**Then** 报告允许评估本机回环网页，但仍不启动网页；在没有另一次明确批准前，网页实现 MUST NOT 出现。
3. **Given** 连续三轮为无净收益，**When** 查看门禁或请求扩充，**Then** 暂停对应新增能力，复盘记录可追加，既有连接/状态/交接/裁决合同保持可用。
4. **Given** 有人把网页、远程界面或本机工作台声明为任务正本，**When** 提交，**Then** 失败关闭，原 `github` / `gitlab` / `local` 正本不变。

### User Story 4 - 公开仓只留方法与脱敏聚合，私有明细进不去 (Priority: P1)

操作者可以把试点的口径说明和脱敏聚合结果放进公开材料：结论分布、度量名称、比较方法。内部项目名、本机路径、Session 标识、凭据、议题正文、用量明细和原始基线数据必须留在私有环境。门禁用合成夹具，不读取真实客户仓库，不把试点原始文件提交进公开仓。

**Why this priority**: Constitution 要求公开核心、研究外置。这是 Issue 的必须交付与明确不做的交汇点。

**Independent Test**: 公开产物夹具不含私有标识；试图把原始明细写入公开路径或版本库的提交被拒绝；合成夹具可在无网络门禁中复现度量与门禁。

**Acceptance Scenarios**:

1. **Given** 一份只含口径与聚合计数、不含项目名与路径的摘要，**When** 作为公开材料提交，**Then** 接受，且当前视图或公开文档不出现内部标识。
2. **Given** 输入含本机绝对路径、内部项目名、客户仓库、Session 标识、凭据或按工作项列出的用量明细，**When** 请求写入公开仓或公开文档，**Then** 拒绝。
3. **Given** 运行本模块门禁，**When** 使用合成夹具，**Then** 不访问真实网络、不要求私有基线文件，也能判定度量槽与扩充门禁。
4. **Given** 本仓库的忽略规则与目录约定，**When** 检查是否为试点原始数据建立了被忽略的研究资料区，**Then** 不存在该类目录约定，私有数据不得以「本地忽略」为名进入本仓。

---

### Edge Cases

- 未记录任何试点时，不得因本模块存在而改变已交付命令的成功/失败合同。
- 试点记录不是授权，不是工作项完成证明，也不是外部议题状态。
- 同类比较由操作者显式声明比较类别；系统不得凭议题标题或客户名自动归类。
- 不足三轮时结论整体为数据不足，不得用一轮好结果批准网页。
- 三轮净收益仍不等于已经实现网页，也不等于 `0.1.0` 已发布。
- 若另一次批准允许网页：仅本机回环、前台运行、拒绝非本机绑定；该实现不在本 Draft 的默认交付内。
- 缺失墙钟、用量或基线不得写成 `0`，也不得把估算标成实测。
- 写者冲突、损坏账本、未知必需合同沿用既有失败关闭。
- 未知子命令、会商 Runtime、出站 Session、把界面当任务正本：仍明确失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 操作者 MUST 能针对已连接 Project 中一项已有交接与验收结论的工作记录一份效能试点。未记录时 MUST NOT 改变既有连接、状态、交接、裁决与可选引擎合同。
- **FR-002**: 每份试点 MUST 引用既有工作身份，MUST 有且仅有一个结论，取值只能是净收益、无净收益、权衡、数据不足或失败。用单一用量或自动化步骤数宣称成功 MUST 失败关闭。
- **FR-003**: 每份试点 MUST 具备规范列出的度量槽：规划墙钟、执行墙钟、总墙钟、人工协调时间、零效果尝试、协调唤醒、返工、设置成本、可取得的原生用量。每个槽 MUST 区分实测、不可用与数据不足。
- **FR-004**: 协调唤醒、零效果尝试与返工 MUST 按产品规范从 Hufu 已有事件派生，MUST NOT 复制议题正文或裁决正文，MUST NOT 另建第二套任务生命周期。
- **FR-005**: 编排墙钟 MUST 只统计操作者驱动的协调间隔；无法观测的模型推理时间 MUST 归入执行墙钟或标为不可用。MUST NOT 摊派估算。MUST NOT 把缺失墙钟写成 `0`。
- **FR-006**: 只有 Host 或 Provider 原生返回的用量才能标为实测。字符估算、缺失值或人工猜数 MUST NOT 标为实测，MUST 为不可用或数据不足，MUST NOT 写成 `0`。
- **FR-007**: 人工基线 MUST 作为带来源与观测时间的观测事实导入。基线 MUST NOT 被写成 Hufu 权威任务状态。含本机绝对路径、内部项目名、凭据或客户标识的基线 MUST 拒绝。
- **FR-008**: 净收益结论 MUST 同时声明授权、安全、结果质量与证据完整性未因缩短时间或降低用量而退化。缺少该声明 MUST NOT 得到净收益。
- **FR-009**: 扩充门禁 MUST 基于操作者声明为同类的试点。不足三轮、或任一轮不是可解释净收益时，MUST 拒绝本机网页、远程绑定、新远程接口及其它新控制面。
- **FR-010**: 即使三轮均为可解释净收益，本模块 MUST NOT 自动实现网页。网页 MUST 另有明确批准后才能进入后续实现。因本 Issue 存在而启动网页的路径 MUST NOT 存在。
- **FR-011**: 连续三轮无净收益时 MUST 暂停对应新增能力并允许复盘记录，MUST NOT 否定已经交付的核心合同，MUST NOT 用更多基础设施掩盖失败。
- **FR-012**: 网页、工作台或其它 Renderer MUST NOT 成为 `task_authority`，MUST NOT 拥有工作项生命周期。
- **FR-013**: 若未来另批网页，其合同 MUST 为：仅本机回环、前台运行、拒绝非本机绑定；两类环境都能以前台方式完成回环验证。该条在本模块默认交付中只作为关闭条件存在，不作为实现授权。
- **FR-014**: 公开仓 MUST 只保留口径、比较方法与脱敏聚合。MUST NOT 保存试点原始数据、内部项目名、本机路径、Session 标识、凭据、议题正文或按工作项列出的用量明细。MUST NOT 建立用于私有试点的被忽略资料目录。
- **FR-015**: Journal、回执、试点结论、当前视图或网页 MUST NOT 被当作执行授权。
- **FR-016**: `connect` / `doctor` / `status` / `handoff` / `decide` / `validate` 的退出码族与机器可读错误合同 MUST 保持。本模块允许增加试点记录与门禁查询，MUST NOT 增加会商或出站命令，MUST NOT 在未批准时增加网页服务命令。
- **FR-017**: 实现任何新的可观察行为前 MUST 先有一条会失败的测试。门禁 MUST 不依赖真实网络、真实客户仓库或私有基线文件。版本保持 `0.1.0`。
- **FR-018**: MUST NOT 引入数据库、消息队列、守护进程、调度器、心跳、配额服务、自动 Agent 启动或外部写回。
- **FR-019**: Windows 与 POSIX MUST 都能完成：记录合成试点、查看度量槽、确认网页门禁关闭，无需后台服务。

### Key Entities

- **PilotInstance**: 一次从目标接受到交接/验收结束的试点记录；指向已有工作，不是新的任务正本。
- **PilotMetrics**: 规范度量槽集合；每槽带来源类别、可用性与是否实测。
- **BaselineComparison**: 私有环境导入的同类人工或单 Agent 对照；观测事实，须脱敏。
- **PilotConclusion**: 唯一结论：净收益、无净收益、权衡、数据不足或失败。
- **ExpansionGate**: 是否允许评估本机回环网页等新控制面；默认关闭。
- **SanitizedAggregate**: 可进入公开仓的口径与聚合，不含原始明细。
- **CurrentView**: 与既有模块同一视图合同家族；可展示门禁与试点引用，不得把它们显示成任务正本或授权。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 按快速开始，操作者能在 15 分钟内于 Windows 或 POSIX 上完成：连接 → 记录一份合成试点 → 查看度量槽与结论 → 确认网页门禁关闭（两类环境各至少一次）。
- **SC-002**: 未记录试点的既有夹具 100% 与本模块之前的连接/状态/交接/裁决结果一致。
- **SC-003**: 合法试点样例 100% 带稳定身份与允许集合内的唯一结论；非法结论或用单一用量/步骤数宣称成功的样例 100% 失败关闭。
- **SC-004**: 合成账本中协调唤醒、零效果尝试、返工的派生结果 100% 可对照规范定义复核；缺失墙钟或用量的槽位 100% 不是 `0`，也 100% 不是冒充的实测。
- **SC-005**: 含本机路径、内部项目名或原始明细的公开材料样例 100% 被拒绝；脱敏聚合样例 100% 不含这些标识。
- **SC-006**: 可比较试点不足三轮，或任一轮不是净收益时，网页/远程/新控制面请求 100% 被拒绝且不出现后台监听。
- **SC-007**: 三轮净收益样例 100% 只打开「允许评估网页」的门禁报告，100% 不因此启动网页服务。
- **SC-008**: 把网页或工作台写成任务正本的输入 100% 失败关闭。
- **SC-009**: 门禁 100% 不依赖真实网络或私有试点文件；公开仓不出现试点原始数据目录约定。

## Assumptions

- 本模块用户是本公开仓维护者。真实代表性试点在私有环境由维护者执行；公开仓与门禁用合成夹具证明合同，不采集客户项目。
- 本模块默认交付试点记录、度量派生与扩充门禁。本机回环网页不在默认交付内；即使门禁打开，仍须维护者另一次明确批准（例如新的 Module Issue 或对本 Issue 的书面加批）才可实现。
- 「同类」由操作者在记录时声明比较类别，不从外部议题标题自动推断。
- 人工基线可以缺失；缺失时该对照槽为数据不足，整份试点仍可记录为数据不足，但不得据此打开网页门禁。
- 结论枚举与产品规范一致：`NET_BENEFIT`、`NO_NET_BENEFIT`、`TRADEOFF`、`DATA_INSUFFICIENT`、`FAIL`。规格正文用中文陈述，实现字段名在 Plan 固定。
- 不新增守护进程，不新增远程服务。查询门禁沿用既有前台命令边界。
- 版本保持 `0.1.0`。本模块不阻塞 `0.1.0` 发布。合入本模块不等于正式发布，也不等于网页已交付。
